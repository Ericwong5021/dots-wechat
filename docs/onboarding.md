# 由已有 dot 完成首次安装

本文供接受 README 安装指令的 dot 执行。用户的操作是授权、本人用微信扫码和发一条测试文字；安装与检查由 dot 完成。不得要求用户用手动终端作为能力不足时的替代步骤。

## 先检查执行与图片能力

开始任何登录前，确认以下事实：

1. 你能在用户本人授权的 Mac/Linux 执行、读写本次新建目录，支持所需 Node.js（`>=22.13`）。普通云容器或文件下载能力不等于能操作用户电脑。
2. 你能向**当前用户私聊**发送原生私有图片附件，并能从上述本机读取此次生成的二维码 PNG。Markdown `file://`、本机路径和浏览器预览不等于用户收到图片。
3. 你能保持有界登录进程、取得非敏感状态、取消进程并清理此次二维码。安装用户侧网关与在 ChatGPT 注册/启用插件是独立能力，逐项核对。

如果缺少能力，只报告具体阻塞，例如“我只有云端执行环境，不能安装到你的 Mac”或“我能执行本机命令，但当前私聊没有私有图片附件工具”。可以完成已获授权且不依赖缺失能力的源码审阅；停止依赖该能力的步骤。不要请求旧凭据、公开上传二维码、绕过交互确认或要求用户手动执行命令。没有附件能力时不要先申请登录二维码。

## A：公共源码安装与无凭据自检

从 [实际仓库](https://github.com/Ericwong5021/dots-wechat)读取 README、AGENTS.md、许可证、锁文件及当前 CLI 帮助。记录本次使用的 commit。在用户批准的本机新建隔离安装目录，避免覆盖已有仓库；不要扫描旧配置、其他项目或聊天记录。

由 dot 执行依赖安装、本地测试、微信与 MCP CLI 的 `--help`，再运行根目录 `npm run doctor`。doctor 不读凭据：在内存中生成合成二维码，并实际启动禁用模式的 loopback MCP 检查，有界运行后自动关闭。它不申请登录二维码，也不调用真实腾讯/OpenAI消息服务。

当前 root `npm start` 启动本机前台服务：`127.0.0.1:8890`、`/mcp` 与 `/healthz`，最长 30 分钟，真实 backend 禁用；identity 为 `dots-wechat-local`。另行手动启动用于检查时，由 dot 核对健康、目录发现和受保护操作拒绝，随后停止；端口占用时不结束不明进程。

向用户报告“安装与无凭据自检通过”及版本、测试结果；不报“微信已绑定”“插件已启用”或“dot 已接通”，除非另有对应实测证据。当前仓库本地合成测试不证明新的安装环境或真实账号可用。

## B：明确授权后，本人扫码新绑定

在请求二维码前，把实际本机新状态目录、二维码的私有附件传输与清理方式展示给用户，并取得明确同意。可使用这段授权说明，补入本次实际位置：

> 允许我为你本人申请一个新的微信 bot 绑定，只在这台获授权的电脑的上述指定私有目录保存此次新凭据，并把本次临时二维码作为当前私聊的私有图片附件发给你吗？二维码附件可能被聊天平台保留，本机清理不会删除平台副本。你本人扫码并在微信确认。本轮仅接收你本人发给此 bot 的纯文本私聊，并只对本轮指定随机标记尝试一次事先批准的固定回复；不读取旧凭据、群聊或其他联系人，不开公网入口、Tunnel、OAuth或Events订阅。

只有真实会话中的同意明确覆盖上述新 bot、本人扫码、指定路径的新凭据和私有二维码附件/平台保留后，dot 才使用以下已定义接口。`ABSOLUTE_NEW_LEAF` 必须换为向用户展示并获准的实际绝对新叶目录；不是让用户复制到终端的命令。

```text
node src/weixin/cli.mjs login --state-dir ABSOLUTE_NEW_LEAF --agent-confirmed-consent --agent-consent-scope new-binding,owner-scan,local-credentials
```

两个 agent flags 只作非 TTY 技术声明，不是授权凭据，不产生或扩大用户同意。不能提前填写、替其他人同意、删安全校验或调用测试注入路径。如果安装的 commit 不支持该契约，报告版本不符并保持 B 未开始；先更新获准版本并完成自检，不让用户转去敲终端。

代理登录须保留以下边界：新状态叶目录事前不存在；父目录属于本人、已存在且权限为 `0700`；新凭据目录 `0700`、`credentials.json` `0600`；不覆盖、不导入旧 token；只使用已审阅的固定腾讯原点。二维码目录 `0700`、PNG `0600`，只取本次成功响应对应的图像，不猜路径、不缓存复用。

CLI 首次输出一条 JSONL `QR_READY`，包含 `qrPngPath`、`generatedAtMs`、`localWaitDeadlineMs`、`privateArtifact: true`、`providerExpiryKnown: false`。dot 只读取本次返回的实际 PNG，作为当前私聊的私有原生图片发给用户，说明“请本人用微信扫码并在微信确认”；保持**同一登录进程**轮询，不为显示图片另发登录请求，也不把路径或 JSON 回执当成已送达附件。

本地等待最多五分钟，腾讯可能更早使二维码过期；`localWaitDeadlineMs` 不是官方到期时刻。用户主动中止返回 `BINDING_INTERRUPTED`，本地等待到期返回 `LOCAL_BINDING_DEADLINE`，真正的传输失败另报错误；不把本地期限说成腾讯到期。代理模式遇到验证码返回 `AGENT_VERIFICATION_CODE_UNSUPPORTED`，暂停本轮并报告当前接口不支持，不绕过验证。未审阅的新原点、旧绑定导入或未知状态也停止。

同一进程只有在官方 `confirmed` 且安全保存成功后输出 `BOUND`，这时才能报告本机绑定成功；扫描状态或附件发出均不够。完成、取消、超时或失败后清理此次本机二维码。私有附件可能由聊天平台保留，不能宣称本机删除会同时删除附件；如平台提供附件删除能力，再按实际回执记录。进程崩溃/强杀可能留下本机 PNG，恢复时只清理能确认是本次创建的临时文件，不遍历其他数据。

## C：一次随机文字收发

由 dot 生成不含私人信息的新随机标记和一条明确说明“dot 自动回复尚未接通”的固定回复。用户授权了 B 的单次范围后，dot 启动有界验证，再把标记发给用户，让本人在此 bot 私聊发送完全一致的纯文字。

当前 `verify` 精确匹配全文，仅允许本人来源；默认最多 3 次轮询、60 秒总期限，每次轮询最多 10 秒。可用范围为 `--max-polls` 1–10、`--timeout-seconds` 1–120。指定 `--reply-text` 才发送；同批多条匹配拒绝发送。使用本次新凭据和私有持久状态，保留去重；结果未知不重试，不删除状态后补发。

记录入站、一次发送尝试和 API 结果，再请本人确认同一私聊实际看到了完整回复。HTTP 200、`API_ACCEPTED` 只算对应协议事实，不能替代本人可见确认。用户确认后只报告“微信网关单条双向收发通过”；固定回复不是 dot 思考后的自动回答，也没有验证 D。

## D：已有 dot 持续多轮文字自动回传

此阶段尚未验收，不包含在 A/B/C 的授权里。须先给用户具体方案和新的授权请求：实际组织与原 dot 工作区、一条传输路径及权限/费用、真实主体授权和微信 owner 映射、callback 验证与签名、有限期限订阅、撤销步骤和数据范围。

未经批准不创建 Tunnel、公网端点、OAuth client/key/grant，也不订阅 Events。普通 MCP 发现或本机网关启动不能代替插件注册、可信身份和原 dot 的事件订阅。安全模型未完成时，不把私聊正文传给 dot。

目标是连续多轮本人纯文本经**已有目标 dot**自动回答并回到原微信私聊，不能以一次固定回复或一次自动回答结束验收。此能力当前尚未验收，下面是必须完成的验收要求，不是已支持的操作：

1. 本人在授权期限内发送多轮不同随机内容，逐轮关联入站、真实 Events 订阅/callback、原 dot 的可见事件和真实回传工具调用、微信业务回执，以及同一私聊的可见答案。分别记录延迟，不把 callback 2xx 或 API 接受当成最终送达。
2. 验证重复事件/消息/工具调用不会重复发信，迟到、撤销和过期回传会被拒绝；结果未知仍不自动重发。
3. 在经过批准的范围内验证受控断线与网关重启恢复：持久状态和去重记录被保留、旧请求不误发、恢复后的新轮次仍能完成。不要通过删去重文件、无限重连或偷偷延长订阅来通过测试。
4. 将每轮及断线/重启的结果交由本人核对，全部所要求场景通过才记录 D 阶段验收。安全模型、持久订阅或真实原 dot 证据不足时，明确保留未通过项。

官方机制见 [MCP Events](https://developers.openai.com/plugins/build/mcp-events)。语音与双向文件只记录为 D 通过后另行授权的下一阶段，此次不开发、不接入、不声称已支持。

## 停止、撤销与报告

用户要求停止时，dot 取消并关闭本轮进程，拒绝继续发送。停止进程、安装授权和 login 授权不自动授权删除凭据。删除本机凭据前，向本人展示确切的规范绝对状态目录，说明将删除其中 `credentials.json` 与 `verify-state.json` 并在成功后移除空目录，以及这不会吊销远端绑定或 token；取得当前真实会话中的明确同意。

获准后，由 dot 使用当前源码的安全代理入口，路径必须换为实际获准目录：

```text
node src/weixin/cli.mjs logout --state-dir ABSOLUTE_APPROVED_EXISTING_DIRECTORY --agent-confirmed-consent --agent-consent-scope local-credentials,local-verify-state
```

两个 flags 只作非 TTY 技术声明，不是加密 owner 证明，不产生或扩大用户授权；不能代填旧 TTY 确认或复用 login scope。活动锁、未知文件、gateway state、不安全目录/文件或身份变化均停止，本轮不强删锁、不递归清理、不扫描旧目录。版本不支持该入口时报告具体阻塞，保持撤销未执行。

`LOCAL_LOGOUT` 仅表示本轮指定范围的本地清理完成；`remoteRevocation: NOT_ATTEMPTED`、`remoteRevocationConfirmed: false` 表示远端未尝试、未证实。`LOCAL_LOGOUT_UNKNOWN` 表示本地整体清理未确认完成，结合逐文件已确认事实报告部分结果，不自动重试或擦除剩余状态。命令不猜测腾讯远端 revocation API。用户在微信实际界面处理远端解绑，以对应实际证据核对。本地删除不能作为远端吊销证明。若未来 D 创建了资源，还须分别核对 unsubscribe、grant、隧道和新运行 key 的撤销。

最终逐项报告 A/B/C/D 的“通过、未执行、失败或阻塞”，给出必要的脱敏证据和下一步。不得把二维码、token、账号 ID、聊天正文、原始响应或私人截图写入 Git、公开 issue、安装报告或测试日志。
