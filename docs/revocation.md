# 停止与撤销

停止进程、本机删除凭据和远端解绑是三个不同动作。分别核对结果，不能把其中一个写成全部已撤销。

## 结束本地实验

1. 在登录、验证或 `npm start` 的前台终端按 **Ctrl-C**，等待退出。不要结束未知进程，也不要留下后台轮询。
2. 在微信 bot 会话停止发送测试文字。若一次发送结果未知，保持防重记录，不自动重发。
3. 确认本机 MCP 端口不再服务；进程退出不代表微信远端 token 已失效。

## 撤销微信绑定

由本人在实际微信界面查找该 bot 的绑定/授权管理并解除本次绑定；界面名称和可用操作以账号实际显示为准。本项目未核实可用的远端 revoke API，因此不提供虚构的一键注销命令。如果找不到入口，记录“远端撤销未确认”，按腾讯实际支持渠道处理。

远端处理后，停止所有相关进程，再删除此次实验的本机凭据与状态。先确认下面路径确实是本教程新建目录，并确认没有需保留的私人证据：

```sh
cd ~/project/dots-wechat
node src/weixin/cli.mjs logout --state-dir "$(pwd -P)/.runtime/weixin-local"
```

`logout` 要求交互终端，并由本人精确键入 `DELETE LOCAL DOTS WECHAT`。它删除本机 `credentials.json`、`verify-state.json` 与空的绑定目录；发现未知文件时拒绝删除，不清理其他账号或项目。

此操作会丢失本机保存的恢复与防重信息。它只能证明本机文件被删除，不能证明远端 token 被吊销、云备份被清除或磁盘已安全擦除。日后测试使用新绑定，不通过丢弃状态重试旧消息。

## 如果未来另行批准了 dot 接入

当前未创建隧道、OAuth grant 或真实 Events 订阅；现在没有这些远端资源要清理。若后续批准并创建，维护者必须补齐与真实实现对应的撤销步骤，至少包括：

1. 立即在可信本地授权层撤销 grant/binding、取消队列并持久化拒绝记录，拒绝迟到回传。
2. 在原有 dot 取消监视，核对实际 `events/unsubscribe`，断开本次插件。
3. 在实际认证提供方撤销此次 client 授权。已签发 access token 的失效机制须实测；不要宣称删除登录文件或撤销 refresh token 会立即使离线 JWT 无效。
4. 停止 relay 与 tunnel 客户端，在控制面删除此次隧道/工作区关联并撤销本次新运行 key。
5. 对本地停止、订阅取消、grant 撤销、隧道删除、凭据撤销分别记录成功或未知，不填写未经确认的“全部完成”。
